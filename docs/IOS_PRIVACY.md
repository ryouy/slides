# ART SLIDE iOS — プライバシー整理（App Store Connect の申告用）

作成日: 2026-11-19 / 対象: ブランチ `ios-swiftui` の実装。根拠が確認できなかった箇所は「未確認」と書いています。

用語は Apple 公式「App privacy details」（https://developer.apple.com/app-store/app-privacy-details/）に従います。

- **収集（collect）**: データを端末の外へ送り、「送信された要求をリアルタイムで処理するのに必要な期間より長く」自分または第三者パートナーがアクセスできる状態にすること。端末内だけの処理は収集ではない。
- **ユーザーとの関連付け**: アカウント・端末・その他の情報でユーザーの身元に結び付けられているか。
- **トラッキング**: アプリから得たユーザー／端末のデータを、第三者データと結び付けて広告やその効果測定に使うこと、またはデータブローカーに共有すること。

## 1. データの流れ

| 送信先 | 何が送られるか | 送られる条件 | 向こうでの保存 |
|---|---|---|---|
| Apple（StoreKit / App Store） | 購入・復元の処理 | Premium を購入・復元するとき | Apple が管理（アプリは受け取らない） |
| Apple（Sign in with Apple） | サインイン要求（スコープなし＝名前・メールは要求しない） | 設定でサインインしたとき | Apple が管理 |
| 自前の Worker `slides.ryouy.workers.dev`（Cloudflare） | ① Apple の ID トークン＋nonce（＋認可コード） ② 同期するパズル記録の JSON ③ Premium 作品のダウンロード時に Apple 署名付き購入情報（JWS） | ①サインイン時 ②同期をオンにしたときだけ ③Premium 作品の取得時 | 下記「2. D1 に保存するもの」 |
| Google（AdMob / UMP） | 広告リクエスト、同意状態、広告識別子（ATT 許可時） | Free ユーザーで同意が得られているとき。Premium では広告を読み込まない | Google が管理 |
| Apple Server Notifications → Worker | 自分のアプリの購読の更新・返金・失効（Apple から Worker へ） | Apple が送る | 下記 |

アプリが送らないもの: 名前、メールアドレス、自分の写真、未完成のパズル、アプリ設定、購入情報（記録同期には含まない）。

## 2. Cloudflare D1 に保存するもの

| テーブル | 内容 | 備考 |
|---|---|---|
| `apple_accounts` | 独自アカウント ID、Apple の `sub`、作成日時 | 名前・メールは保存しない |
| `apple_sessions` | セッショントークンの SHA-256、アカウント ID、期限（90 日） | トークン自体は保存しない |
| `apple_sync` | アカウント ID、版番号、同期 JSON（最大 512KB）、更新日時 | 中身は3ゲームの記録のみ |
| `apple_tokens` | Apple の refresh token（AES-GCM で暗号化）| アカウント削除時の認可失効のためだけ。Secret 未設定なら保存しない（実装中: `worker/appleAccount.ts`） |
| `apple_subs` | 購読の original transaction ID、有効期限、返金フラグ、最後の通知種別 | Apple のサーバー通知から作る。アカウント ID・記録とは結び付けない |
| `rate_limits` | `appleauth:<IP の HMAC ハッシュ（32桁）>` と回数、窓の開始時刻 / `applesync:<アカウント ID>` と回数 | 乱用防止のみ。窓（10分／1時間）が終わった行は次の窓の開始時に上書きされ、24時間より古い行は次の窓の開始時に削除される |

Web 版（別機能）の `users`（Google の `sub`・表示名）、`subscriptions`、`sessions` は iOS 版からは使いません。

## 3. 端末内に保存するもの（外へ送らない）

`Application Support/Records/*.json`（3ゲームの記録・進行中のパズル・設定）、`ArtDownloads/`（取得した Premium 作品）、`CustomPhotos/`（自分の写真）、Keychain（セッショントークン）。購入状態は StoreKit が端末に持つ署名付き取引から都度判定します。

## 4. SDK のプライバシーマニフェスト（実物）

ビルド済みアプリに同梱されている `PrivacyInfo.xcprivacy` を読みました（GoogleMobileAds 13.13.0、UserMessagingPlatform 3.1.0）。

| データ | Google Mobile Ads | UMP |
|---|---|---|
| デバイス ID | 関連付け **あり**、トラッキング **あり**（サードパーティ広告・分析・自社広告） | — |
| 広告データ | 関連付け **あり**、トラッキングなし | — |
| 製品の操作 | 関連付け **あり**、トラッキングなし | 関連付けなし（アプリの機能） |
| おおよその位置情報 | 関連付け **あり**、トラッキングなし | 関連付けなし（アプリの機能） |
| クラッシュデータ | 関連付けなし | — |
| パフォーマンスデータ | 関連付けなし | 関連付けなし（アプリの機能） |
| その他の診断データ | 関連付けなし | — |
| トラッキングドメイン / `NSPrivacyTracking` | 宣言なし | 宣言なし |
| 必須理由 API | SystemBootTime / UserDefaults / DiskSpace | UserDefaults |

Google の公開ページ（https://developers.google.com/admob/ios/privacy/data-disclosure）は、データの種類と目的を挙げていますが、「関連付け」「トラッキング」の別は書いていません。そのため、**関連付け・トラッキングの判断には SDK 同梱のマニフェストを根拠にしました**。

### 以前の宣言との矛盾について

以前のアプリ本体のマニフェストは、デバイス ID・広告データ・製品の操作・おおよその位置情報を「関連付けなし」と宣言していました。SDK 自身のマニフェストは、この 4 つを「関連付けあり」としています。実際にデータを送るのは SDK なので、SDK の宣言に合わせて **「関連付けあり」が正** です。アプリ本体のマニフェストからは、SDK が自分で宣言しているデータ（上の表の SDK 由来の行）の重複記載を外しました（Apple の仕様では、Xcode が SDK のマニフェストを集約します）。

Release 構成のアーカイブ（署名なし）を作って確認しました。アプリ本体と上の 2 つの SDK の、計 3 つの `PrivacyInfo.xcprivacy` が含まれていました。Xcode の「Generate Privacy Report」（Organizer の GUI 機能）は、この環境では実行していません（未確認）。

## 5. App Store Connect で選ぶ内容

「このアプリまたはサードパーティパートナーはアプリからデータを収集しますか？」→ **はい**

| データの種類 | 収集 | 使用目的 | ユーザーとの関連付け | トラッキング | 根拠 |
|---|---|---|---|---|---|
| ユーザー ID | する | アプリの機能 | あり | しない | Apple の `sub` と独自アカウント ID を D1 に保存（サインインした人のみ） |
| ゲームプレイのコンテンツ | する | アプリの機能 | あり | しない | 同期した記録を D1 に保存（同期をオンにした人のみ。Apple の定義「保存したゲームなど」） |
| デバイス ID | する | サードパーティ広告、分析、デベロッパの広告またはマーケティング | あり | **する** | AdMob（広告識別子。ATT 許可時）。SDK のマニフェスト |
| 広告データ | する | サードパーティ広告、分析、デベロッパの広告またはマーケティング | あり | しない | SDK のマニフェスト |
| 製品の操作 | する | サードパーティ広告、分析、デベロッパの広告またはマーケティング、アプリの機能 | あり | しない | SDK のマニフェスト（Google）と UMP |
| おおよその位置情報 | する | サードパーティ広告、分析、デベロッパの広告またはマーケティング、アプリの機能 | あり | しない | SDK のマニフェスト（IP などから。ユーザーが許可している場合） |
| クラッシュデータ | する | 分析 | なし | しない | SDK のマニフェスト |
| パフォーマンスデータ | する | サードパーティ広告、分析、デベロッパの広告またはマーケティング、アプリの機能 | なし | しない | SDK のマニフェスト（Google と UMP） |
| その他の診断データ | する | サードパーティ広告、分析、デベロッパの広告またはマーケティング | なし | しない | SDK のマニフェスト |
| 購入履歴 | **しない** | — | — | — | 下記 §6 |
| 名前 | しない | — | — | — | サインインでスコープを要求しない。コード上どこにも名前を読まない |
| メールアドレス | しない | — | — | — | 同上 |
| 写真またはビデオ | しない | — | — | — | 自分の写真は端末内だけに保存し、送信しない |
| 連絡先、位置情報（正確）、財務情報、健康、機微情報、閲覧履歴、検索履歴、その他のデータ | しない | — | — | — | 取得・送信するコードなし |

補足: 「ユーザー ID」と「ゲームプレイのコンテンツ」は、サインインして同期をオンにした人だけのデータですが、機能がある以上、申告は必要です。Apple の「任意の開示」の条件（トラッキング・広告に使わない、まれで任意、ユーザーが毎回明示的に提供…）をすべて満たさないため、除外できません。

## 6. 「購入履歴」を申告するか

結論: **申告しない**（現在の実装に基づく）。

- Apple の定義は「アカウントまたは個人の購入、または購入の傾向」で、「収集」は「リアルタイム処理に必要な期間より長くアクセスできる状態にすること」です。
- アプリが Worker へ送る Apple 署名付き取引（JWS）は、Premium 作品を渡してよいかをその場で検証するためだけに使い、**保存しません**（`worker/apple.ts`: 検証して破棄。ログにも出さない）。これは「リアルタイム処理に必要な期間」内の利用で、収集に当たりません。
- D1 の `apple_subs` は、**Apple のサーバーが Worker へ送る通知**から作る行です（アプリが端末から送ったものではありません）。original transaction ID と期限・返金フラグだけで、アカウント ID・パズル記録・端末情報とは結び付けていません。
- 購入そのものは StoreKit と Apple が処理し、アプリは購入者の情報を受け取りません。
- 前提が崩れる場合: JWS やその一部をログ・DB に保存するようにしたとき、または購入情報をアカウント ID と結び付けたとき（再検討が必要）。

未確認: Workers の呼び出しログ（observability）に、リクエストヘッダー（`Authorization` に JWS が入る）が自動で残るかは、公式ページに記載がなく確認できていません。ダッシュボードの Workers Logs でサンプルのリクエストを見て、`Authorization` が含まれていないことを確認してください。含まれていた場合は上の前提が崩れます。

## 6.5 サインイン・同期・削除の実装（コード確認済み）

- サインインはスコープなし（名前・メールは要求しない）。Apple の ID トークンと nonce、認可コード（失効用）だけをサーバーへ送る。
- セッショントークンは Keychain に保存（端末のみ、iCloud 同期なし）。サーバーにはハッシュだけ。
- 同期は設定で明示的にオンにしたときだけ。対象は 3 ゲームの記録のみ（自分の写真・未完のパズル・設定・購入は対象外）。
- アカウント削除: サーバー側のデータ（アカウント・セッション・同期データ・暗号化トークン）を先に必ず削除し、そのあと Apple の認可失効を試みる。失効が失敗・未設定でも削除は成立し、アプリは Apple 設定からの解除手順を表示する。
- 別のアカウントでサインインしたときは、前のアカウントの記録が混ざらないよう、端末の記録（3ゲーム）をいったん消してから、そのアカウントの記録を取り込む（前のアカウントのデータはサーバーに残る）。

## 7. Cloudflare のログと IP アドレス

- **レート制限の IP**: `cf-connecting-ip` を `SESSION_SECRET` による HMAC にして 32 桁に切り詰め、回数とともに `rate_limits` に保存します。秘密鍵なしでは元の IP に戻せません。ただし **`SESSION_SECRET` が未設定だと、単純な SHA-256 になり、総当たりで元に戻せます**（本番で `SESSION_SECRET` が設定されていることを確認してください）。保存は乱用防止のためだけで、アカウント ID とは結び付けていません。残る期間は上の表のとおり（窓が終わった後、次の窓の開始時に上書き／24時間を過ぎた行は削除）。
- **Apple の分類への影響**: 「IP のハッシュ」は Apple のデータ種類の一覧に直接の項目がありません。乱用防止（Apple の目的区分では「アプリの機能（セキュリティ・不正防止）」に近い）のための短時間のカウンタで、ユーザーとは関連付けていないため、**現状は申告項目に加えていません**。ただし、Apple がこれをどの項目として扱うかは公式資料で明示されておらず、**未確認**です。
- **Workers Observability**（`wrangler.jsonc` で有効）: 公式ドキュメントによると、呼び出しごとに 1 件のログ（リクエスト・レスポンスと関連メタデータ）が残ります。どのフィールド（IP、ヘッダーなど）が入るかは記載がなく、**未確認**です。保持期間は Workers Free で 3 日、Workers Paid で 7 日（上限 7 日）。アクセスは Cloudflare アカウントのダッシュボードから。アカウントのどのロールが見られるかは**未確認**です。無効化するには `invocation_logs = false` を設定できます（Web 版の運用ログにも影響するため、今回は変更していません）。
- **アプリのコードが出すログ**: 認証情報（`Bearer …` やキー）は伏せ字にし、エラー名と短いメッセージだけです（`worker/safeLog.ts`）。トークンや JWS、同期データは出しません。

## 8. AdMob・ATT・UMP

- UMP（Google の同意フォーム）→ ATT → SDK 開始の順。UMP で広告が許可されていない場合、広告は読み込みません。
- ATT を拒否・未決定の場合、SDK は広告識別子を使いません。アプリは、独自に第三者データと結び付けるコードを持ちません。
- 同意（UMP）を取ったことを、ATT の許可とは見なしません。ATT は独立して iOS のダイアログで確認します。許可の有無で、アプリの機能や課金特典は変わりません。
- Premium（StoreKit 検証済み）の場合、広告ビュー自体を作らないので、広告の読み込み・送信は起きません。StoreKit の判定が出るまで広告は出しません。
- 設定画面に、UMP が求める地域では「広告のプライバシー設定」を表示します。
- `PrivacyInfo.xcprivacy` の `NSPrivacyTracking` は **true**（アプリに組み込んだ広告 SDK が、ATT 許可時に広告識別子をトラッキング目的で使うため）。SDK はトラッキングドメインを宣言していないので、アプリ側にも `NSPrivacyTrackingDomains` は空です（宣言がないものを推測で足していません）。

## 9. 開発者が確認・設定すること

1. App Store Connect の「アプリのプライバシー」を、上の §5 の表のとおりに入力する。
2. Xcode で Product → Archive → Organizer → Generate Privacy Report を実行し、集約された内容が §4・§5 と合っているか確認する（この環境ではアーカイブを作っていません）。
3. Workers Logs でサンプルのリクエストを確認し、`Authorization` ヘッダーや JWS が残っていないことを確認する（§6）。
4. 本番 Worker に `SESSION_SECRET` が設定されていることを確認する（§7）。
5. Apple の認可失効用 Secret（`docs/APPLE-SETUP.md`）を設定する。
6. 審査メモに、Sign in with Apple（任意）とアカウント削除の場所（設定 → アカウント → アカウントを削除）を書く。
