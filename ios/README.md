# ART SLIDE for iOS (SwiftUI)

A native SwiftUI app. ART SLIDE is the main game; WORD SLIDE and BIG SLIDE are mini-games opened from the home screen's **Menu** sheet. The look follows the web version; behaviour is native (tap + drag gestures, springs, haptics, sheets, StoreKit 2, AdMob). The web site is unchanged and built separately.

## What is where

| Path | What |
|---|---|
| `ios/App/` | Xcode project: only the `@main` entry (`SlideApp.swift`), Info.plist, entitlements, `PrivacyInfo.xcprivacy`, assets, `Premium.storekit` |
| `ios/SlideKit/Sources/SlideCore/` | Game logic, Foundation only: `Art/`, `Word/`, `Big/`, RNG (identical to the web's), JST date keys, JSON file persistence, UI strings loader |
| `ios/SlideKit/Sources/SlideKit/` | SwiftUI: `Shell/` (app model, settings, Premium, ads, images/downloads), `Art/`, `Word/`, `Big/` |
| `ios/SlideKit/Tests/SlideCoreTests/` | Tests, incl. **golden vectors generated by the web code** (`Golden/*.json`): the same seed gives the same puzzle as the web |
| `ios/scripts/export-*.ts` | Export web data into the app bundle (`ios/App/App/public`, git-ignored): UI strings (7 languages), paintings metadata, free paintings + all thumbnails, word list, golden vectors. Fails if a Premium full-size image would be bundled |
| `ios/scripts/ios-strings*.json` | iOS-only UI texts (English + Japanese; other languages fall back to English) |
| `ios/Config/*.xcconfig` | Bundle ID, Team, product id, AdMob ids, version |
| `worker/apple.ts` | Server side: Apple-signed transaction check, Premium painting download, App Store Server Notifications V2 |

## Build

Requirements: Xcode 16+ (tested with Xcode 27.2), Node 22.

```bash
npm install
npm run ios:data            # REQUIRED before building: generates ios/App/App/public (data + images)
open ios/App/App.xcodeproj  # Run on a simulator (iOS 17+)
# or:  cd ios/App && xcodebuild -project App.xcodeproj -scheme App -destination 'generic/platform=iOS Simulator' -derivedDataPath build CODE_SIGNING_ALLOWED=NO build
```
If `xcodebuild` says it needs Xcode: `sudo xcode-select -s /Applications/Xcode.app/Contents/Developer`.
After adding paintings to the web data run `npm run ios:data` again (new paintings are Premium unless added to `src/premium/freeList.ts`; the iOS daily pools in `src/games/art-slide/logic/dailyPickIos.ts` are frozen copies: append a new pool with a future date to add free paintings to the rotation).

DEBUG-only launch arguments (compiled out of Release): `-skipConsent`, `-debugPremium`, `-artScreen home|menu|daily|gallery|play:<id>|stats|how|credits|photos`, `-wordScreen …`, `-bigScreen …`.

## Values you provide

`ios/Config/Local.xcconfig` (git-ignored) overrides `Shared.xcconfig`: `PRODUCT_BUNDLE_IDENTIFIER`, `DEVELOPMENT_TEAM`, `PREMIUM_PRODUCT_ID`, and (for testing a Release build with other ids) `ADMOB_*`. The Bundle ID `com.ryouy.artslide` and the team are set in the Xcode project.
Also change `com.ryouy.artslide.premium.monthly` in `ios/App/Premium.storekit` to your product id when testing purchases locally.

## Premium / in-app purchase (StoreKit 2)

1. Apple Developer → Identifiers: register the Bundle ID. App Store Connect → My Apps → New App with that Bundle ID.
2. Subscriptions → create a group, then an **auto-renewing monthly** product with your `PREMIUM_PRODUCT_ID`; set the price (about JPY 200) and localizations; add the Terms/Privacy URLs to the app page.
3. Local test: Xcode → Product → Scheme → Edit Scheme → Run → Options → StoreKit Configuration = `Premium.storekit`. Run on the simulator, subscribe (no real charge). Debug ▸ StoreKit ▸ Manage Transactions lets you expire, refund and cancel to test those paths.
4. Sandbox test: use a Sandbox Apple Account on a real device (App Store Connect → Users and Access → Sandbox).
5. Server (Cloudflare Worker): set `APPLE_BUNDLE_ID` and `APPLE_PRODUCT_ID` as Secrets/Variables. Premium painting downloads answer 503 until both are set. Set `APPLE_ALLOW_SANDBOX=true` **only** while testing with Sandbox/TestFlight; remove it for production.
6. App Store Connect → App → App Information → App Store Server Notifications → set the **Production** and **Sandbox** URL to `https://<your worker>/api/apple/notifications` (version 2). This delivers renewals, expiry and refunds. (The table `apple_subs` is created automatically.)

How Premium is decided: StoreKit remains authoritative on the device (including offline use). After optional account sign-in, the app sends its Apple-signed transaction to the Worker; it is re-verified (certificate chain pinned to Apple Root CA G3, bundle id, product id, expiry, revocation, Sandbox flag) and can be explicitly linked to the existing Google/Stripe account. A valid linked Stripe subscription or a valid linked Apple subscription grants Premium. The two subscriptions are never converted or automatically cancelled.

## Account & sync (optional)

Nothing requires an account. Settings > Account offers Sign in with Apple; once signed in, **Sync records** (off by default, an explicit switch) keeps the game records in step between devices.
- **Syncs:** per game the daily history, personal bests, play history (newest 200), clear counters and per-painting records. **Never syncs:** Premium / purchases (StoreKit decides that on each device), the visitor's own photos and their records, unfinished puzzles, preferences, the current endless streak.
- **Merging** (`SlideCore/Sync`, pure and unit-tested: idempotent, commutative, associative): daily history = union by date, the better clear (lower time, then fewer moves) wins; bests = per-key minimum of time and of moves; play history = union (an identical record on two devices is one play), capped at 200; counters = max (an undercount is possible, double counting is not); per-painting clears = max; daily streaks are computed from the merged history. Flow: GET, merge with the local files, write locally (only after the remote document decoded; a newer `schema` is left untouched and shows "update the app"), PUT with `baseVersion`; HTTP 409 merges the returned document and retries (at most 3). Runs at launch, on returning to the foreground, when the network is back, and about 5 s after a game saves records. Any failure shows "try later" and keeps local records as they are.
- The session token is stored only in the Keychain (this device, `AfterFirstUnlock`, not iCloud). Sign out clears it and turns sync off and never touches records; Delete account asks the server first and keeps the device's records (the account stops owning them). A 401 drops the session.
- **Switching accounts never clears anything by itself.** The app remembers (as a SHA-256 only) which account the records were last synced with and a digest of the records right after that sync. If a different account signs in, sync pauses and Settings asks: (a) *Bring this device's records into the new account* (adds them to the new account by the normal merge), (b) *Use only the new account's records* (offered only when the device has no records that were not synced yet; a safety copy `Records/switch-backup.json`, one slot, is written first, then only the records of the three games are cleared, never puzzles in progress, preferences or own photos), or (c) Cancel / dismiss (the new session is signed out again, nothing local changes). Records never synced to any account are adopted by the first account that syncs, without a question. Logic and tests: `SlideCore/Sync/SyncOwnership.swift`.
- **Server setup:** the Worker needs `APPLE_BUNDLE_ID` and the D1 migration `npx wrangler d1 migrations apply slides-db --remote`; until then the endpoints answer 503 and the app just reports it could not sync. The app needs the Sign in with Apple capability (already in the entitlements). The client sends Apple's `authorizationCode` at sign-in so the Worker can revoke the Apple authorization on account deletion (`revoked` in the delete answer; when it is not `revoked` Settings tells the person how to remove the authorization by hand).
- Privacy manifest and App Store Connect answers: User ID and Gameplay Content, linked to the user, not used for tracking, purpose App Functionality.
- Debug launch arguments: `-openSettings`, `-debugSignedIn` (shows the signed-in layout; no token, nothing is sent), `-debugSwitchPrompt` / `-debugSwitchPromptKept` (show the account-switch dialog with / without the replace choice).

## Google sign-in & Drive sync (optional, ART SLIDE records only)

Google sign-in also signs into the ART SLIDE common account using a server-verified OpenID token. Thus an existing web Google account with an active Stripe subscription is Premium on iOS without an Apple purchase. This basic sign-in does **not** request Drive access. Drive remains a separate opt-in switch below. When an Apple account is signed in, the user must explicitly choose “Link this Google account”; both credentials are verified server-side and an existing link is never replaced automatically.

A second, separate way to keep records in step: **Sign in with Google** (Settings > Google Drive) and then **Sync records with Drive**. It does not replace or change the Apple account / Worker sync above.
- **Same file as the web version:** the records live in the hidden Drive `appDataFolder` file `slides-art-records.json` (scope `https://www.googleapis.com/auth/drive.appdata`), in the web app's exact JSON format (`src/sync/doc.ts`, schema 1). `SlideCore/Sync/Drive` is a Swift port of the web's `mergeDocs` / `local.ts`; golden vectors written by the web code (`npx vite-node ios/scripts/export-drive.ts` -> `Tests/SlideCoreTests/Golden/drive.json`) check that merges, `normalizeDoc`, save-to-document and document-to-save give identical results. Counts are kept per device (this install has a `deviceId` in the ART save), so two devices never count a clear twice. Only ART play records go to Drive: never WORD / BIG, purchases, the visitor's own photos, unfinished puzzles or preferences.
- **Opt-in like the web:** signing in asks only for the basic profile; the Drive permission is requested when the person turns Drive sync on (and that is when it syncs at once). Turning it off disconnects at Google (access withdrawn; this also ends the Google session on the device) and keeps local records and the Drive file. The app never reads, stores or sends the person's name or e-mail (only a SHA-256 of Google's opaque account id is kept, to notice an account switch). An expired or revoked token drops back to signed out with a short notice.
- **Syncs** at launch, on returning to the foreground, when the network is back and about 5 s after records change; after uploading it reads the file once or twice more to merge a concurrent write from another device. A newer-schema or damaged Drive file is never overwritten; any failure shows "try later" and leaves local records untouched.
- **Account switch** (a different Google account than the one that last synced these records): the same confirmation as above (bring in / use only the new account's records, offered only without unsynced records and after a safety copy `Records/drive-switch-backup.json` / cancel). Nothing is cleared automatically.
- Using both this and the Apple/Worker sync on the same device is allowed, but they merge counters differently (the Worker takes the larger value); if you only need one, turn the other off to avoid inflated totals.
- **Setup:** `ios/Config/Shared.xcconfig` carries `GOOGLE_IOS_CLIENT_ID` and `GOOGLE_REVERSED_CLIENT_ID` (public identifiers; `Local.xcconfig` can override them). They are mapped to `GIDClientID` and a `CFBundleURLTypes` scheme in `Info.plist`; the redirect is handled in `SlideRoot` with `.onOpenURL { GIDSignIn.sharedInstance.handle($0) }`. If the client id is empty or `invalid.apps.googleusercontent.com`, the Google section is hidden. To create a client: Google Cloud Console > the SAME project as the web client > APIs & Services > Credentials > Create credentials > OAuth client ID > iOS, bundle ID `com.ryouy.artslide`; enable the Google Drive API; OAuth consent screen > add the scope `drive.appdata`.
- **Not verified here:** real Google sign-in, real Drive reads/writes, and that the web and iOS clients really see the same `appDataFolder` file. The appDataFolder is scoped per Google Cloud project (OAuth client project), so sharing needs the iOS and web clients in the same project; it was reported to be, but this could not be checked from this machine.
- Privacy manifests of the added packages (GoogleSignIn 8, AppAuth, GTMAppAuth, GTMSessionFetcher, GoogleUtilities, Promises) are bundled with the app. `GoogleSignIn` declares, all linked to the user and not for tracking: Name, Email Address, Phone Number, Other Data Types, Coarse Location, User ID (purposes App Functionality, some also Analytics), Device ID and Other Usage Data (Analytics), plus UserDefaults reason CA92.1. The others declare no collected data (UserDefaults reasons CA92.1 / C56D.1 / 1C8F.1 only). The app's own `PrivacyInfo.xcprivacy` is unchanged.
- Debug launch arguments: `-debugGoogle` / `-debugGoogleOn` / `-debugGoogleOut` (fake "signed in", "signed in with sync on", "signed out" for screenshots; no network), `-debugGoogleSwitch` (shows the account-switch dialog).

## Ads (AdMob)

Adaptive banner only (no interstitial / rewarded / app-open). Shown to Free users on calm screens (home, gallery, results), never next to a board in play; hidden for Premium (and until StoreKit has answered once), offline, when ads are not allowed, or when an ad fails (no blank space).
Order at launch: Google UMP consent (where required) → App Tracking Transparency (only if ads may be requested, only while the app is active; the answer changes nothing in the app) → SDK start. If consent was given in an earlier session the SDK starts immediately. Settings shows "Ad privacy settings" when UMP requires it.

* **Debug builds use Google's TEST ids** (Shared.xcconfig). **Release builds use the production ids** (Release.xcconfig): app id `ca-app-pub-5121019112887429~2282860353`, banner unit `ca-app-pub-5121019112887429/2800193115`, publisher `pub-5121019112887429`. Never click real ads while testing; register your device as a test device in AdMob if you run Release on it.
* DEBUG-only launch arguments (compiled out of Release): `-skipConsent` (skips UMP/ATT pop-ups for screenshots), `-debugPremium`.
* `PrivacyInfo.xcprivacy` declares tracking = true (Google Mobile Ads, after consent) with the data types Google documents for AdMob; the SDKs ship their own manifests and tracking domains. Keep App Store Connect → App Privacy answers consistent with it (Device ID, Advertising Data, Product Interaction, Coarse Location for third-party advertising; Crash/Performance data for app functionality; tracking: yes).
* `app-ads.txt` lives at the domain root `https://ryouy.github.io/app-ads.txt` (repo `ryouy/ryouy.github.io`) with `google.com, pub-5121019112887429, DIRECT, f08c47fec0942fa0`. In App Store Connect set the app's **Marketing/Developer website to `https://ryouy.github.io/`** so AdMob looks at that domain, then press "Check for updates" in AdMob → Apps → app-ads.txt (verification can take up to 24 h after the app is live on the App Store).
The web site keeps using AdMax.


## Offline behaviour

* Bundled: 40 free paintings (full size), all thumbnails, metadata and licences, UI texts, word list, all game logic.
* iOS daily painting: only from the 40 free paintings (frozen pools; each cycle of 40 reshuffled). Date numbers and the 0:00 JST rollover are the same as the web; WORD / BIG SLIDE dailies are the web's generators ported (identical puzzles).
* Premium paintings: downloaded once (Settings can download all / delete all) into Application Support, playable offline afterwards.
* Records are JSON files in Application Support (atomic writes + backup copy); a damaged file falls back to the backup, then to defaults.

## Before every upload: check the privacy manifests

Apple rejects (ITMS-91064) a manifest with `NSPrivacyTracking` = true and no tracking domains, or false with some. The app's own manifest is
`NSPrivacyTracking` = false with **no** `NSPrivacyTrackingDomains` key (see `docs/IOS_PRIVACY.md` §11). After Product → Archive run:

    npm run ios:check-privacy -- "<archive>.xcarchive/Products/Applications/App.app"

It checks every `PrivacyInfo.xcprivacy` in the build (app, frameworks, SDK bundles) and must end with "all N manifest(s) valid". Raise
`CURRENT_PROJECT_VERSION` in `Config/Shared.xcconfig` for every upload (Build 2 is the first after the rejection).
